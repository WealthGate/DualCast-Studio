# v0.6.46 — VST2 validation and audio transport fixes

Prepared for release; the published release remains v0.6.45 until installers are published.

Some effects and their dependencies write diagnostic text to stdout. The audio host previously shared that pipe with its framed audio output, so diagnostic text could be mistaken for malformed audio and cause the effect to be bypassed. The host now reserves the audio pipe before loading plugin code and redirects CRT/Win32 diagnostic output away from PCM.

The host validates the processing interface after Open and sample-rate/block-size setup, supports the legacy accumulating float32 callback with cleared output buffers, and reports plugin initialization/license failures separately from malformed interfaces. MIDI instruments receive an explicit unsupported message; ReaStream remains a supported audio effect.

Status parsing preserves split UTF-8 metadata and ignores bounded third-party logs. Host events begin on a new line, and probe completion waits for pending status data before reporting an exit failure.

Preset restoration is identified before calling into plugin code. If a plugin crashes or stalls there, the app reports a saved-settings failure and explains how to create a fresh registration while retaining the previous preset on disk. The installed ReaControlMIDI DLL reproduced this crash with its own saved chunk; its internal restore implementation is not changed. Local Virtual Mix Rack and SSL DeEss initialization timeouts also remain vendor-side troubleshooting cases, rather than proof of invalid DLLs.

Verification includes the unit suite and typecheck, native fixture regression checks, installed ReaEQ/ReaStream PCM processing, the noisy legacy fixture UI workflow, installed ReaStream scan/enable/editor/bypass, and the native AudioWorklet bridge. Network reception still needs rehearsal with the actual ReaStream sender and matching identifier.
